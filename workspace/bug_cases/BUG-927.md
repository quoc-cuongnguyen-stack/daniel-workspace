# BUG-927: Asynchronous Reverse Geocoding Error When Moving Pin Location & Duplicate City Display in View Profile

> **Status:** ✅ Fixed
> **Date Found:** 2026-08-07
> **Date Fixed:** 2026-08-07
> **Project:** SSL (ssl-fe-user, ssl-be)
> **Severity:** 🟠 High

---

## 🔍 Description

When a user drags or moves the location pin on the map within `View Profile => Update Location`, the city and country input fields did not update to reflect the new pin coordinates, causing backend reverse-geocoding to be skipped. Additionally, the View Profile header rendered city and country text redundantly across both the profile bio line and the map card overlay.

## 🔄 Reproduction Steps

1. Open `View Profile => Update Location`.
2. Move/drag the pin on the map to a different city or country.
3. Observe that the input dropdowns for City and Country stay stuck on the previous values.
4. Click Update: Location in the database retains the old `countryId`/`cityId` with the new pin coordinates.
5. In View Profile, observe duplicate city/country text rendered on the bio line and map card.

**Expected behavior:** Moving the pin should update city/country resolution via reverse geocoding on update, and profile header location text should be rendered cleanly without duplication.
**Actual behavior:** City/Country inputs remained stuck and backend reverse geocoding was skipped because `countryId` was sent in the payload. Profile header rendered duplicate location labels.

## 🧠 Root Cause Analysis

1. In [edit-location-modal.tsx](file:///Users/daniel/Projects/CyberSkill/SSL/ssl-fe-user/src/modules/profile/(components)/edit-location-modal.tsx), `handleLocationChange` only updated `map.latitude` and `map.longitude` in state `formData` while keeping `countryId` and `cityId` set to old values.
2. In [user.util.ts](file:///Users/daniel/Projects/CyberSkill/SSL/ssl-be/src/modules/user/user.util.ts), `applyReverseGeocoding(payload)` checked `if (!payload['countryId'] ...)`. Since `countryId` was non-empty in the frontend payload, backend reverse geocoding was skipped.
3. In [profile-header.tsx](file:///Users/daniel/Projects/CyberSkill/SSL/ssl-fe-user/src/modules/profile/(components)/profile-header.tsx), location text was rendered as `{displayCityName}, {displayCountryName}` under user bio, and repeated on the map card overlay as `{displayCountryName}, {displayCityName}`.

## 🔧 Fix Applied

- **Frontend**:
  - Updated `handleLocationChange` in [edit-location-modal.tsx](file:///Users/daniel/Projects/CyberSkill/SSL/ssl-fe-user/src/modules/profile/(components)/edit-location-modal.tsx) to clear `countryId` and `cityId` when coordinates change from pin movement.
  - Simplified location text in [profile-header.tsx](file:///Users/daniel/Projects/CyberSkill/SSL/ssl-fe-user/src/modules/profile/(components)/profile-header.tsx) to prevent duplicate city display and handle identical city/country names gracefully.
- **Backend**:
  - Updated `applyReverseGeocoding` in [user.util.ts](file:///Users/daniel/Projects/CyberSkill/SSL/ssl-be/src/modules/user/user.util.ts) to execute reverse geocoding whenever `countryId` or `cityId` is empty or missing.

## 🧪 Unit / Regression Test

- **Test File:** [user-reverse-geocoding.test.ts](file:///Users/daniel/Projects/CyberSkill/SSL/ssl-be/src/modules/user/user-reverse-geocoding.test.ts)
- **Command:** `pnpm test src/modules/user/user-reverse-geocoding.test.ts`
- **Test Results:** Asserted that `applyReverseGeocoding` executes nearest city resolution when `countryId` or `cityId` is empty, and skips when both are valid non-empty strings.

## 📝 Lessons Learned

- Form state for location pins should invalidate pre-selected city/country references when pin coordinates are manually dragged.
- Backend reverse-geocoding guards must handle empty string values (`""`) and missing `cityId` rather than solely checking falsy `countryId`.
